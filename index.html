Security-by-Design: Frontend Sanitization & Backend RLS

1. Sanitización de Entradas en Frontend (Prevención XSS) Client-Side Protection

Cada texto ingresado por el usuario en el formulario (nombre, dirección, notas) es filtrado mediante funciones de escape HTML para evitar inyección de código ejecutable (<script>).

const sanitizeHTML = (str) => str.replace(/[&<>"']/g, match => ({ '&': '&', '<': '<', '>': '>', '"': '"', "'": ''' })[match]);
2. Regla de Base de Datos Supabase (Row Level Security) PostgreSQL RLS

Los precios y nombres visibles provienen del catálogo. Aunque un usuario manipule el precio localmente en el inspect del navegador, el backend en Supabase re-valida y rechaza modificaciones no autorizadas mediante la siguiente política:

CREATE POLICY "Solo lectura de catálogo público"
ON public.productos FOR SELECT USING (activo = true);
3. Previsualizador del Payload codificado (WhatsApp API) URI Encoding

El resumen del pedido se construye como una cadena estructurada codificada de forma segura con encodeURIComponent() antes de abrir el endpoint de WhatsApp.
